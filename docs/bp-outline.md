## 1. 问题与洞察

> 来源：PRD §3.1 + `docs/bp-facts.md`

**一句话主张：小白的第一笔亏损，往往不是投资失败，而是被骗。**

**页面要素**
- 三个「缺」（PRD §3.1）：**看不懂** / **辨不出** / **不知道自己该冒多少风险**
- 数据三连（全部出自 `bp-facts.md`，每条标注来源与年份）：

| 数字 | 说明 | 出处 |
|---|---|---|
| **68,907 人** | 2025 年全国起诉电信网络诈骗犯罪人数 | 最高检《刑事检察工作白皮书（2025）》 |
| **7% 的发案，38% 的钱** | 虚假网络投资理财类诈骗只占电诈发案 7%，却占被骗金额 38%（北京市） | 北京市公安局 2025-10-28 发布会 |
| **平均 36.7 天** | 从诈骗分子首次接触到受害者报警的时长（北京市） | 同上 |

**讲稿**

> 打开任何财经平台，信息是过剩的，不是稀缺的。小白缺的不是资讯，是三样东西：看不懂、辨不出、不知道自己该冒多少风险。
>
> 而最贵的那一课是「辨不出」。北京市公安局今年 10 月的数据：虚假网络投资理财类诈骗只占电诈发案数的 7%，但占了被骗金额的 38%。**它是单位破坏力最大的一类。**
>
> 但同一份数据里还有一个数字更值得注意：**平均 36.7 天**。从骗子第一次接触受害人，到受害人报警，平均隔了三十六天。
>
> 这意味着骗局不是一瞬间完成的——**有一个月的窗口期。来得及拦。**

⚠️ 口径纪律：7%/38%/36.7 天是**北京市**数据，讲的时候必须说「北京市公安局的数据」。

## 2. 被骗的人不是不懂理财的人（洞察页，建议单独一页）

> 来源：`docs/bp-facts.md` §2.1 + PRD §3.2

**一句话主张：「多数有专业投资理财经历」——投教救不了他们，识别才行。**

**页面要素**
- 北京市公安局原话直接上屏（加引号、标出处）：
  > 「受害者中 46 岁以上的占六成，60 岁以上的占二成，目前年龄最大的男性和女性均为 88 岁；**多数有专业投资理财经历**。」
- 右侧放三个用户画像的**极简卡片**（PRD §3.2）：小陈 24 岁 / 王阿姨 63 岁 / 小李 20 岁
- 一行结论：**养老诈骗案件里，六成是非法集资**（最高法数据，`bp-facts.md` §2.2）

**讲稿**

> 这一句是我们整个产品的立项理由：**「多数有专业投资理财经历。」**
>
> 被骗的不是不懂理财的人。所以「把人教聪明」这条路救不了他们——他们已经不算小白了，还是中招了。
>
> 真正缺的不是知识，是**当场、逐句、有依据的话术识别**。这就是财智通和所有投教类产品的分界线。

## 3. 为什么选这条路（差异化，核心论点页）

> 来源：PRD §2.3

**一句话主张：所有走「帮你赚钱」路线的项目，天花板都被合规按住了。**

**页面要素**
- 左右对比图：
  - 左「帮你赚钱」：AI 荐股 / AI 荐基 / 买卖信号 → **红色**，标注「须持牌，我们和多数团队都没有」
  - 右「帮你不被骗」：投资者保护 / 投资者教育 / 反非法金融活动宣传 → **绿色**，标注「监管明确要求金融机构履行的义务」
- 底部一句话：**这条路上，合规不是成本，而是护城河。**

**讲稿**

> 同赛道大概会有很多团队做「AI 投顾助手」。但在现行监管下，AI 荐股违法、AI 荐基违法、AI 给买卖信号违法。**所有走「帮你赚钱」路线的项目，天花板都被合规按住了。**
>
> 我们反向选择：走监管鼓励的方向。投资者保护和投资者教育，是《证券法》《反电信网络诈骗法》和各级监管部门明确要求的义务。
>
> 同样一件事，别人做要牌照，我们做是监管鼓励。**合规在这里不是成本，是护城河。**

- **智能体协作表**（PRD §4.2，挑 3 条上屏，这是「系统而非拼盘」的证据）：

| 触发 | 联动 |
|---|---|

## 5. 技术亮点（这一节是技术分，建议 3 页）

### 5.1 核心架构：判定归规则，转述归模型

> 来源：PRD §5.3 / §8.3 / CLAUDE.md §3

**一句话主张：风险等级、命中项、法规依据全部由确定性规则产生，模型只负责「提取」和「讲人话」。**

**页面要素** —— 六步流水线图，每步标注是「规则」还是「模型」：

```
① 视觉识别  模型 │ OCR 提取原文
② 规则比对  规则 │ 15 类特征 / 365 关键词（高精度）
③ 语义识别  模型 │ 覆盖口语与变体（高召回），引文必须真实存在
④ 主体核查  规则 │ 资质、性质、渠道疑点 + 官方核查入口
⑤ 法规引证  规则 │ 为每条命中调取法规条文
⑥ 汇总裁决  模型 │ 把客观判定转述成大白话
   输出审查  规则 │ 六类越界表述硬拦截 + 编造数字检测
```

**讲稿**：模型只在两头出现——头上认字，尾巴上讲人话。**中间的判断全是确定性代码。换模型不影响判定结果。**

### 5.2 双通道：规则保证「说的都对」，语义保证「该发现的不漏」

> 来源：PRD §17

**一句话主张：关键词库永远穷举不完，所以我们有第二条通道；但第二条通道的每句话都必须可验证。**

**页面要素**
- 触发这次修改的**真实失败**（这个失败要讲，很有说服力）：
  > 输入「把钱全给我，我一定帮你炒股赚大钱」→ 第一版系统判 🟢 **暂未发现明显问题**
  >
  > 根因：特征库是照着「正规广告文案」建的（保本保息、预期年化），
  > 而真实骗局在微信里说的是大白话（把钱给我、我帮你炒、一定赚）。**两套语言，只覆盖了一套。**
- 语义通道的**三条硬约束**：
  1. 只能从既有特征分类表中选，不得自创类别 → 法规引证依然成立
  2. **必须给出原文中真实存在的引文，引文对不上直接丢弃**
  3. 引文要过与规则通道完全相同的否定/科普语境检查
- 双通道实测表（PRD §17「效果实测」，挑 4 行上屏）

**讲稿**

> 如果评委问「你们的关键词库能穷举所有骗术吗？」——**答案是不能。** 所以我们有第二条通道。
>
> 那模型会不会乱说？它给出的每一条都必须引用原文中真实存在的片段，**引文对不上我们直接丢弃**，而且报告里会把丢弃的项列出来给你看。

### 5.3 模型选型是实测选出来的，不是拍脑袋

> 来源：PRD §16

**页面要素** —— 选型表（qwen-vl-plus 1.7s 采用 / qwen-flash 1.9s 采用 / qwen-plus 4.4s 弃用）
**关键一行**：qwen-plus 被弃用的原因不是慢，是它**自己补出了「银行大额存单才 2% 左右」这个我们无法核实的数字**。

**讲稿**：我们因此加了**编造数字检测**——比对模型输出与原文中的数字，一旦出现原文没有的数值，**整段丢弃、回退模板**。

## 6. 合规设计（本项目最硬的一节）

> 来源：PRD §8.1 / §8.3 + `docs/legal-check.md`

**一句话主张：我们不做法律定性，只输出「命中的违规表述特征」和「核查指引」。**

**页面要素**
- **三区边界表**（PRD §8.1）：🔴 禁止 / 🟡 谨慎 / 🟢 放心做，标出我们每个功能落在哪一区
- 措辞对照（这个细节很打动评委）：

| ❌ 不能说 | ✅ 我们说 |
|---|---|
| 这是诈骗 | 该内容命中 N 条监管明令禁止的表述特征 |
| 这个产品安全 | 未识别到违规表述特征。这不构成对该产品的安全性保证 |
| 建议配置 20% 股票基金 | 权益类参考比例 20% |

- **输出审查层**三道防线：判断依据外置 / 输出确定性审查 / 全链路可溯源
- **法规库已逐条核对**：14 条法条全部 `verified: true`，每条带 `sourceUrl`，评委可当场点开

**讲稿（这段建议背下来）**

> 我们做了一件很少有团队愿意花时间做的事：**14 条法条逐条打开官方原页面核对。**
>
> 核对过程中真的查出并改正了 3 处错误。其中一处是条号错了——把《证券法》第一百六十一条的内容标成了第一百六十条。还有一处更隐蔽：我们原来引的刑法第一百七十六条，是**刑法修正案（十一）之前的废止文本**——网上大量二手资料至今还是旧的。
>
> 过程有记录，在 `docs/legal-check.md`。**这三处错误恰好证明了：不核对是真的会错的。**

## 7. 商业模式（方向三「重点考察」，必须给足）

> 来源：PRD §11.1 / §11.2 / §11.3

**一句话主张：我们不创造需求，我们替代现有的低效手段——发传单、贴海报、开讲座。**

**页面要素**
- 核心逻辑一句话：投资者教育与反非法金融活动宣传，是**监管强制要求、且有真实预算科目**的事
- 收入路径表（PRD §11.2 原表）：

| 客户 | 付费理由 | 产品形态 | 优先级 |
|---|---|---|---|
| 银行 / 券商 | 投资者适当性管理与投教是**监管硬性义务**，需留痕、需可考核 | 白牌工具 + 投教活动数据报告 + 适当性匹配辅助 | P0 |
| 社区 / 街道 / 老年大学 | 反诈宣传自上而下推动，**年年有预算**，现有手段效果差 | 反诈体验终端 + 活动包 + 效果报告 | P0 |
| 高校 | 财商教育、防范校园贷进课表 | 课程包 + 闯关系统 + 班级数据看板 | P1 |
| C 端个人 | 免费 | 流量与数据入口，反哺规则库 | — |

- **为什么不做 C 端订阅**（PRD §11.3）：人们低估自己被骗的概率，C 端为「防骗」付费意愿低；
  B/G 端是**合规驱动的刚性支出**，决策链清晰、预算科目明确

**可以引用的支撑**（来自 `bp-facts.md`，说明 B/G 端需求是真的）：
- 最高检《刑事检察工作白皮书（2025）》把**「投资理财」列为非法集资专项行动重点领域之首**
- 公安部刑侦局、国家反诈中心《2025 版防范电信网络诈骗宣传手册》把**「虚假网络投资理财」列为 10 类高发之一**，
  且官方自己的方法论也是「关键词 + 套路拆解」——手册提炼了 20 个防诈关键词。
  **我们做的是把这套官方方法论自动化、即时化。**

## 8. 数据飞轮

> 来源：PRD §11.4

**一句话主张：用得越多，识别越准。这是护城河。**

```
C 端用户上传可疑广告
   → 沉淀真实骗局样本与新变体话术
   → 规则库与特征库持续更新
   → 识别准确率提升
   → B/G 端产品竞争力提升
   → 收入 → 投入内容与技术
```

**讲稿**：C 端免费不是补贴换增长，是**换样本**。骗子的话术每周都在变，而只有真实上传量能让规则库跟上。

## 10. 竞品与边界：和国家反诈中心 App 的关系

> 来源：PRD §10.4

**一句话主张：反诈 App 管通讯与交易层，我们管内容与话术层。互补，不是替代。**

**页面要素** —— 两栏对比：

| 国家反诈中心 App | 财智通 |
|---|---|
| 通讯与交易层拦截 | **内容层合规体检** |
| 涉诈号码、短信、App 黑名单、转账预警 | 一张广告图、一段群聊、一份说明书 |
| 管「已经发生的接触行为」 | 管「话术本身」 |
| 不承担投教职能 | 同时输出法规依据与投教 |

**讲稿**：投资理财骗局的入口是**内容**——一张图、一段群聊、一份说明书。**这些不在号码黑名单里。**
