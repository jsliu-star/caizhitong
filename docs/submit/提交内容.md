## ⑤ 核心创新点

表单可以「添加一条」，建议填 5 条。每条给了短版和长版，输入框窄就用短版。

### 1. 判断不交给模型

短版
```
风险等级和法规依据都由代码算出，换个模型结果一样。模型只负责认字和讲人话。
```

长版
```
风险等级、命中了哪几条、依据哪条法规，全部由确定性代码算出来，换个模型结果一样。模型只做两件事：认出图上的字，把结论讲成人话。这样「AI 会不会乱说」就不再是个信任问题，而是架构上已经决定了的事。
```

### 2. 关键词穷举不完，所以加了第二条通道

短版
```
关键词库覆盖不了口语，第二条通道交给模型识别，但引文对不上原文就丢掉。
```

长版
```
骗子的说法无穷多，关键词库永远穷举不完。所以第二条通道交给模型，去认「钱打过来我帮你操作」这类大白话。但它必须引用原文里真实存在的句子，引不上就直接丢掉，丢掉了哪几条还会列出来给用户看。
```

### 3. 模型说完还要再过一道审查

短版
```
越界的说法直接拦掉，出现原文里没有的数字就整段作废，不靠提示词自觉。
```

长版
```
模型写完的话不直接给用户看，先过一层代码审查：越界的说法直接拦掉，出现原文里没有的数字就整段作废、退回模板。最容易出错的是「没发现问题」这一档，模型在这里最爱下结论，所以那一档干脆不让它开口。
```

### 4. 不只说现在有问题，还说下一步

短版
```
按命中特征预告对方接下来会做什么，用户可以自己等着看准不准。
```

长版
```
报告不只说现在这段话有问题，还会预告对方接下来会做什么，比如「他会让你先提一小笔钱出来，好让你敢投更多」。这是可以被验证的判断，用户自己等着看准不准，比一句「请提高警惕」有用得多。
```

### 5. 不做需要牌照的那部分

短版
```
推荐股票基金要牌照，我们只做监管鼓励的投教和反诈，没牌照也能合规运营。
```

长版
```
推荐具体股票基金属于证券投资咨询，要牌照，我们不做。只做监管本来就鼓励的投资者保护和投教，没有牌照也能合规运营。14 条法规逐条核对了官方原文，核对过程中查出并改正了 3 处错误，其中一处引的是已经被修正案废止的旧条文。
```

## ⑥ 作品文件

优先上传 `财智通-作品说明.docx`。表单写的是「支持文档」，Word 最通用。

三种格式都备好了：

| 文件 | 用途 |
|---|---|
| `财智通-作品说明.docx` | 首选。Word，含 11 张表格 |
| `财智通-作品说明.html` | 浏览器打开后打印成 PDF |

docx 是直接写 OOXML 生成的，没用 macOS 自带的 textutil。textutil 会把表格全部拍平成一行行段落，11 张表会散掉。

## 「提交代码」是另一回事，有个坑

第一张截图那个「提交代码」对话框，和「提交作品」不是一件事。它写了两条限制：

**一、文件只能从 AIStudio 工作空间里选，不能从本地上传。** 我们代码在这台机器上，所以那个框现在显示「暂无文件」。得先把项目放进 AIStudio。

**二、只收文本类文件，它列的是 ipynb、py、md、json。** 我们是 Next.js 项目，源码是 `.ts` 和 `.tsx`，都不在这个名单里。后面那个「等」字留了余地，但不保险。

可以这样应对，按稳妥程度排：

1. 在 AIStudio 里放一个 `README.md`，说明这是 Web 应用不是 notebook 项目，附上仓库结构和关键文件清单，再把最能体现技术含量的几个文件用 md 包一层贴进去。md 和 json 都在它明确支持的类型里。
2. 直接提交 `data/` 下的几个 json。法规库、违规话术库、骗局图鉴本身就是项目最硬的资产，而且类型明确受支持。
3. 不要指望上传 `.ts`、`.tsx` 或者压缩包，很可能被拒。

这件事得你先去 AIStudio 看一眼能放什么。我在本地没法替你验证，所以这一项没有先生成文件，免得做了白工。你确认后告诉我，我按它接受的格式打包。
