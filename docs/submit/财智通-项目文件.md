## 二、项目摘要

很多人第一次理财亏钱，不是投资失败，是被骗了。

北京市公安局的数据里，虚假网络投资理财类诈骗只占电诈案件的 7%，被骗的钱却占 38%。更意外的是另一句：受害人「多数有专业投资理财经历」。他们不缺知识，缺的是有人在当时就告诉他，这句话本身就不合规。这类骗局从搭上话到报警平均隔 36.7 天，中间有一个月可以拦。

财智通就做这件事。用户把广告截图、群里转来的话或者产品说明书发进来，系统逐句告诉他：哪几句是监管明令禁止的说法、依据哪条规定的原文、对方接下来可能会做什么。看不懂的术语当场翻成大白话。想理清自己的家底，还有风险测评和两个计算器。

技术上最关键的一个决定是：判断不交给模型。风险等级、命中了哪几条、依据哪条法规，全部由确定性代码算出来，换个模型结果一样。模型只做两件事——认出图上的字，把结论讲成人话。它写的每句话还要再过一道代码审查，出现原文里没有的数字，整段作废。

合规上我们只做监管鼓励的那一半：投资者教育、风险提示、反非法金融活动宣传。不推荐任何具体标的，不预测涨跌，不承诺收益，不作「是否诈骗」的法律定性。14 条法规逐条核对过官方原文并附链接，核对过程中查出并改正了 3 处错误。

商业上，投教和反诈宣传是监管要求金融机构必须履行的义务，有明确预算科目。所以面向机构收费，个人免费。

## 四、项目背景与行业现状

### 1. 行业发展背景

**理财人口在扩大，理财能力没跟上。** 银行理财、公募基金、券商资管的线上化让开户和申购只要几分钟，短视频和社交平台又把理财内容推到了每个人面前。买入变容易了，判断没有变容易。中国人民银行金融消费权益保护局每两年开展一次全国消费者金融素养问卷调查，从金融知识、行为、态度、技能四个方面衡量居民水平，报告公开发布在 pbc.gov.cn。（具体指数得分需在引用前核对官方原文，见附录「待核对」。）

**投资理财类骗局是官方点名的高发类型。** 公安部刑侦局、国家反诈中心《2025 版防范电信网络诈骗宣传手册》梳理了 10 类高发电信网络诈骗类型，「虚假网络投资理财」位列第二。

下面这些数字都来自官方公开页面，链接见附录，可当场点开核对。

| 事实 | 出处 |
|---|---|
| 2025 年全国检察机关起诉电信网络诈骗 68,907 人；起诉网络犯罪 18.2 万人，同比下降 33.3%，「但仍处于高位」 | 最高人民检察院《刑事检察工作白皮书（2025）》，2026-03-10 |
| 2024 年起诉电诈 7.8 万人，同比上升 53.9% | 最高人民检察院工作报告，2025-03 |
| 2025 年起诉金融犯罪 1.3 万件 2.5 万人。白皮书把「投资理财」列为打击非法集资的重点领域第一项 | 同上白皮书 |
| 2017 年至 2022 年 8 月，全国法院审结非法集资一审刑事案件 6.02 万件 10.87 万人；集资诈骗案件重刑率 78.78% | 最高人民法院，2022-09-22 |
| 养老诈骗刑事案件中，非法集资案件约占六成 | 同上 |

**三个数字决定了产品长什么样。** 以下来自北京市公安局 2025-10-28 发布会，**是北京市数据，不是全国数据**。

- **7% 的案子，38% 的钱。** 虚假网络投资理财类诈骗占全市电诈案件的 7%，被骗金额占 38%。被骗 100 万元以上的案件中近七成是这一类。这类骗局单笔损失最大，从这里下手边际收益最高。
- **平均 36.7 天。** 从首次接触到受害人报警，是各类电诈里最长的。骗局不是一瞬间完成的，中间有一个月可以拦。这是我们做「骗局剧本预测」的直接依据。
- **受害人多数有专业投资理财经历。** 同一份通报里 46 岁以上占六成，60 岁以上占二成。被骗的不是不懂理财的人——「把人教聪明」这条路救不了他们，他们缺的是在那一刻有人逐句告诉他：这句话本身就不合规。

### 2. 现存行业痛点

| 痛点 | 具体表现 |
|---|---|
| 信息零散、杂乱 | 同一个概念在不同平台说法不一，用户要自己拼凑，检索成本高 |
| 广告混在信息里 | 内容与营销不分，用户分不清哪句是知识、哪句是话术 |
| 缺中立科普 | 大部分内容由卖方提供，天然带立场；真正中立的投教入口分散且不好找 |
| 科普与决策错位 | 用户在「手里正拿着一张广告、马上要决定转不转钱」的那一刻需要帮助，而科普内容按知识体系组织，帮不上那一刻 |

从用户视角看，缺的是三样东西：

- **看不懂。** 市盈率、年化、IRR、R2 风险等级，看到就懵。
- **辨不出。**「保本年化 12%」和「预期收益 3.5%」在他眼里都是收益，分不出哪个一定是骗局。
- **不知道自己该冒多少风险。** 拿买房首付去追高波动的东西。

市面上的产品几乎都在解决「怎么赚得更多」，很少有人认真做「怎么亏得更少」。对一个刚开始理财的人来说，躲开一次五万块的骗局，比多赚百分之五重要得多。

### 3. 国内外研究 / 产品现状

| 现有形态 | 作用层 | 留下的缺口 |
|---|---|---|
| 国家反诈中心 App 等官方工具 | 通讯与交易层：涉诈号码、短信、App 黑名单、转账预警 | 处理的是「已发生的接触行为」。一张广告图、一段群聊截图、一份产品说明书不在号码黑名单里 |
| 金融机构与行业协会的投教平台 | 知识供给层 | 按知识体系组织内容，服务的是愿意主动学习的人，不服务「此刻正拿着一张可疑广告的人」 |
| AI 投顾 / 智能投顾类产品 | 决策建议层 | 未持牌推荐具体标的属于证券投资咨询业务。合规天花板压得很低，做得越具体越难解释怎么合法运营 |
| 境外的自动化投资顾问与国民金融素养教育项目 | 一头是持牌的投资建议，一头是学校与社区里的素养教育 | 两头都不覆盖「即时、逐句、指向具体条文」的内容层体检 |

**学术与政策研究**多集中在两个方向：金融素养测度与影响因素，以及诈骗行为的犯罪学与心理学机制。前者告诉我们「谁更容易被骗」，后者告诉我们「骗局怎么推进」。两类研究都有共识：**决策当时的即时干预，效果好于事前的一般性教育。** 我们把产品做在这个共识上。

一句话说清我们的位置：**反诈 App 管通讯和交易，投教平台管知识供给，我们管内容层的合规体检。** 三者互补，不替代。

### 4. 项目立项意义

**补普惠金融教育的缺口。** 投资者教育资源集中在有意愿、有时间主动学习的人身上。真正高风险的人群——中老年人、学历不高的普通劳动者、刚有闲钱的大学生——既没有时间系统学习，也不知道从哪学。财智通把学习入口放在「他正需要判断」的那一刻，成本最低、动机最强。

**提升全民金融素养。** 每一次体检都附法规原文和大白话解释，用户是在解决具体问题的过程中学会通用识别方法的。

**保护居民财产安全。** 直接对应最高检把「投资理财」列为重点领域、公安部把「虚假网络投资理财」列为十类高发之一的现实。

**给机构提供可留痕的履职工具。** 投资者适当性管理、投教、反非法金融活动宣传是监管硬性要求，机构现在多靠发传单、贴海报、开讲座完成，效果难考核。我们提供的是可统计、可留痕的替代手段。

## 五、产品功能与演示说明

### 1. 核心功能完整介绍

四个入口。顺序就是价值主张：**先别被骗，再看得懂，才敢规划。**

#### 1.1 识别与翻译（首页）——先别被骗

截图或者文字丢进来，两种模式：

- **风险体检**：逐句比对监管明令禁止的表述特征，出一份报告。
- **条款翻译**：把产品说明书、合同条款翻成大白话，标出真正该看的几个关键点。

风险体检报告包含七块内容：

| 报告模块 | 内容 |
|---|---|
| 风险等级 | 红 / 黄 / 绿三档，由确定性规则算出 |
| 逐条命中 | 命中了哪一类特征、原文哪一句、为什么算 |
| 法规依据 | 每条命中调出对应法规条文，标注是否已核对官方原文，附来源链接 |
| 主体核查 | 资质、性质、渠道疑点，并给出证监会、基金业协会、国家企业信用信息公示系统的官方查询入口 |
| 五维风险画像 | 收益承诺、资质可核验、渠道正规、紧迫压迫、情感操控 |
| 骗局剧本 | 对方接下来可能会做什么，按推进顺序列出 |
| 现在该做什么 | 按紧急程度排序的行动建议 |

术语点开就地解释，不用跳走。信息不足时系统会主动追问，用户的回答拼回原文重跑一遍完整分析。

#### 1.2 学习——再看得懂

| 模块 | 内容 |
|---|---|
| 闯关 | 5 关 25 题，满分 300 分。答错就地讲清为什么错 |
| 识别测试 | 5 段仿真文案，用户先自己判断，再和引擎的判定比一比。判定结果不预存，由服务端实时跑规则引擎，展示的是引擎真实输出 |
| 术语表 | 24 条，点开才展开，不用背 |
| 骗局图鉴 | 9 类骗局、48 步剧本、10 条真实案例，全部出自最高法、最高检、证监会公开发布页 |
| 定向微课 | 按用户在体检里遇到过的特征推送，共 16 条，覆盖全部 16 个规则特征 |

#### 1.3 规划师——才敢规划

| 模块 | 内容 | 合规边界 |
|---|---|---|
| 风险测评 | 自适应问卷，后面的问题随前面的回答变。给出风险类型、综合得分，并指出回答里的自相矛盾 | 只输出风险画像，不输出产品 |
| 大类配置参考 | 按测评结果给出大类资产的参考比例 | 只讲品类和比例原则，不指向任何具体产品 |
| 品类优先级 | 6 步先后顺序，每步都带「做完的标准」：有高息负债先还债、没应急金先攒应急金…… | 只排顺序，不排产品 |
| 投资方向看板 | 12 个方向：名称 + 一句话这是什么 + 近 60 交易日迷你走势 + 区间涨跌 + **振幅**，点开看「风险来自哪里」 | **固定顺序展示，绝不按涨幅排序**（排序本身就是暗示推荐）；涨跌与振幅同时给出 |
| 投资方向科普 | 9 类方向：各自是什么、风险主要来自哪里 | 只讲品类特征 |
| 定向陷阱提醒 | 按画像推送最容易踩的陷阱 | 只作风险提示 |
| 两个计算器 | 分期的真实年化成本（IRR）、应急金该留多少 | 纯计算 |
| 规划师问答 | 可以直接问问题。答什么由规则层决定，模型只负责讲人话 | **越界的问题不是「让模型小心地答」，而是根本不问模型** |

**规划师问答：拒答本身是产品的一部分。**

用户可以直接提问。规则层先做三件确定性的事，模型只拿到规则层允许它讲的素材：

| 步骤 | 谁做 | 内容 |
|---|---|---|
| ① 意图闸门 | 规则 | 5 类越界意图直接模板拒答，不让模型开口：问具体标的（含 6 位证券代码）、问买哪个、问涨跌与买卖时点、问能赚多少、问能不能代操作 |
| ② 档案事实 | 规则 | 从共享档案里取出可用事实，每条都带「依据」，数字全部是算出来的 |
| ③ 可讲要点 | 规则 | 把问题匹配到 12 个允许讲的投教主题（先还债、应急金、大类配置、适当性匹配、锁定期、费用、业绩基准、分散、存款与理财的区别、杠杆、防骗、目标可行性），作为模型的**唯一素材来源** |

拒答不是一句「我不能回答」。每一类都给三段：为什么不能做、能替你做什么、顺带一条投教。例如问「能赚多少」，回答是：承诺或暗示收益是监管明令禁止的表述，我不会给你一个数字；**能算的是反方向——要达成你的目标需要多少年化收益率**，这是纯数学，算完你就知道这个目标是靠攒钱能成，还是在指望一个不现实的收益率。

> **为什么闸门要在模型之前**：推荐具体标的、预测涨跌属于证券投资咨询业务，须持牌。我们没有牌照，所以这类问题不是「让模型小心地回答」，而是**根本不问模型**。拒答本身是产品的一部分——它是守规矩的证据，也是最好的投教素材。

无 API key 或模型超时时，回答退回由规则层的事实与主题拼出的模板，内容不虚，只是文采差些。这一路有 136 项断言覆盖。

**投资方向看板为什么这样设计。** 12 个方向分四组固定展示：宽基（沪深300 / 中证500 / 创业板指）、风格（科创50 / 红利）、行业（白酒 / 医疗 / 新能源车 / 证券 / 有色 / 军工）、固收（国债指数）。数据源是新浪财经公开指数，服务端 60 秒缓存。两个刻意的设计：**固定顺序，绝不按涨幅排序**——排序本身就是暗示推荐；**同时给区间涨跌和振幅**——让收益和波动一起被看到。实测数字最能说明问题：科创50 近 60 日跌 9.5%，振幅 42%；国债指数涨 1.1%，振幅 1%。这两行数字并排放着，比任何风险提示的文案都有说服力。

#### 1.4 我的档案——把三个入口串起来

三个入口共读共写同一份用户画像。字段包括风险类型与得分、回答矛盾、知识掌握情况与薄弱术语、遇到过的骗局特征、负债年化、应急金月数、理财目标。档案只存在用户自己的浏览器里，不上传、不建集中式用户库。

交互上的三个决定：

- **流水线可见。** 六个阶段依次点亮，每一步在做什么、命中了什么、排除了什么，都实时显示。用户看到的是过程，不是一个黑箱结论。
- **术语不跳页。** 点开就地展开，看完接着往下读。
- **老年人友好。** 全站字号可在导航栏里按百分比调节（100%–160%，另给「标准 / 大 / 更大 / 最大」四个预设一步到位），偏好存在本地，任何一页刷新后都保持。

### 3. 智能体自动化工作流程

```
① 视觉识别   模型   从图片原样提取文案、机构名、联系方式
② 规则比对   规则   15 类特征 / 365 关键词，精确通道（保证说出来的都是对的）
③ 语义识别   模型   覆盖规则库穷举不到的口语与变体（保证该发现的不漏掉）
④ 主体核查   规则   资质编号、主体性质、成交渠道疑点 + 官方核查入口
⑤ 法规引证   规则   为每条命中调取对应法规条文
⑥ 汇总裁决   模型   把客观判定转述成小白能懂的话
   输出审查   规则   六类越界表述硬拦截 + 编造数字检测
```

在这条主线之外，还有两条自动化：

**主动追问。** 系统先判断自己缺什么信息，再决定要不要问、问什么。信息足够时一个都不问。用户的回答会被拼回原文重新走一遍完整六阶段分析，所以追问会真的改变结论。

> 实测：用户补充「我转了钱，现在提现失败，对方要求我再交一笔费用才能解冻」后，行动建议第一条从「现在不要转账」变成「【最紧急】不要再交任何解冻金、保证金、税费——这是提现骗局的最后一步」，同时新增一条资金盘运作特征命中，报警与固定证据被提到最前。

**档案联动。** 每条定向提示都显示来源行，比如「依据：规划师测出你的风险偏好偏进取」，让联动能被用户当场验证。档案为空时一条都不出——不虚报联动。

| 档案里的事实 | 别处跟着变 |
|---|---|
| 测评结果偏进取 | 体检页重点提示「高收益」话术——这类人最容易被钓走 |
| 测评结果偏保守 | 体检页重点提示「跟存款差不多」这类混淆存款与理财的说法 |
| 某个术语反复答错 | 该术语出现在广告里时，就地提示回去复习 |
| 遇到过荐股群 | 学习页推送对应微课；骗局图鉴按此重排 |
| 算出负债年化 13% | 全站提示：先还掉确定的 13%，再谈不确定的收益 |
| 年龄段 60+ | 提示放大字号，术语进一步简化，骗局图鉴优先展示针对中老年的类型 |

## 六、技术方案

### 1. 整体技术架构

```
┌─ 浏览器（Next.js App Router / React 19）────────────────────┐
│  识别与翻译   学习   规划师   我的档案                       │
│  共享档案（localStorage，不上传）                            │
└───────────────┬─────────────────────────────────────────────┘
                │ SSE 流式（逐阶段推送进度与命中项）
┌───────────────▼─ 服务端 Route Handler（Node runtime）───────┐
│  智能体流水线                                                │
│    ① 视觉识别 ──┐                                            │
│    ② 规则比对   │  ②④⑤⑦ 确定性代码                          │
│    ③ 语义识别   │  ①③⑥   模型（走统一适配层）               │
│    ④ 主体核查   │                                            │
│    ⑤ 法规引证   │                                            │
│    ⑥ 汇总裁决 ──┘                                            │
│    ⑦ 输出审查（模型自由文本必经）                            │
├──────────────────────────────────────────────────────────────┤
│  规则层  lib/rules/*   计算层  lib/finance, lib/plan/*        │
│  模型适配 lib/llm/*（无 key 自动降级 mock）                   │
│  知识库  data/*.json（可版本控制、可溯源）                    │
└──────────────────────────────────────────────────────────────┘
```

**架构上的一句话原则：判定归规则，转述归模型。** 风险等级、命中项、法规依据全部由确定性代码产生，模型只负责「提取」和「讲人话」。新增任何模型调用都必须保持这条原则：模型的输出要么可验证（引文比对），要么必须经过审查层。

### 2. 核心技术栈明细

| 层 | 选型 | 为什么 |
|---|---|---|
| 框架 | Next.js 16（App Router，Turbopack） | 同一套代码写前后端，Route Handler 直接支持流式响应 |
| 前端 | React 19 + TypeScript 5 | 类型贯穿规则层与页面，报告结构改动能被编译器抓住 |
| 样式 | Tailwind v4，全部走 CSS 变量 | 只做浅色主题，演示环境要可预测 |
| 运行时 | Node 22 | — |
| 模型 | 阿里云百炼：qwen-vl-plus（视觉）+ qwen-flash（文本） | 实测选型，为演示速度而定。走统一适配层，可替换 |
| 图表 | 自研内联 SVG 组件（环形图、雷达图、仪表盘、路径图、指标块） | 不引外部图表库，分类色固定顺序不循环，每处都配直接标签 |
| 测试 | tsx 直接跑 TypeScript 断言脚本 | 零配置，改完立刻能跑 |
| 数据 | 本地 JSON 知识库 + 浏览器 localStorage | 无数据库、无用户表，见 §6 |

### 3. AI 智能体核心能力设计

| 能力 | 怎么实现的 | 它凭什么算「智能体」而不是「表单」 |
|---|---|---|
| 感知 | 视觉识别原样提取图片中的文案、机构名、联系方式 | 输入是用户随手一张截图，不是结构化表单 |
| 判断 | 规则比对 + 语义识别双通道，双通道共用一套排除标准 | 高精度与高召回分开承担，互相不污染 |
| 取证 | 每条命中自动调取对应法规条文，标注核对状态与来源 | 结论可溯源，用户点开就看到依据 |
| 追问 | 先判断自己缺什么信息，再决定问不问、问什么，回答拼回原文重跑全流程 | 系统自己决定要不要问，且追问会改变结论 |
| 记忆 | 共享用户档案，三个入口共读共写，每条联动带来源行 | 跨会话、跨模块的持续画像 |
| 预测 | 按命中特征匹配骗局剧本，预告对方下一步 | 输出的是可被用户自己验证的预测 |
| 拒答 | 意图闸门在模型之前，5 类越界意图直接模板拒答 | 智能体知道哪些问题自己不该答，并说清为什么 |
| 自我约束 | 输出审查层拦截越界表述与编造数字 | 智能体对自己的输出负责 |

### 4. 算法与模型方案

**规则通道（高精度）。** 15 类违规话术特征（硬性违规 8 类 / 高风险诱导 7 类）、365 个关键词。命中后要过三层排除：

| 排除层 | 解决什么 | 粒度 |
|---|---|---|
| 否定语境 | 「本产品**不**保本」不该判违规 | 分句级：检测命中词前同一分句内的否定词 |
| 科普语境 | 「凡是承诺保本保息的**都是骗局**」不该判违规 | 强线索整句范围，弱线索限分句范围 |
| 合法术语白名单 | 「固定收益类」「无风险利率」是规范表述 | 命中片段落在合法术语内部则跳过 |

> 语境粒度是被实测推翻两次后才定下来的：教育语境的线索常出现在违规词的后半句，只看分句必然误判；而弱线索若放到整句范围，真实广告里一句「警惕错过」就能让整段违规话术蒙混过关。

**语义通道（高召回）。** 关键词库穷举不完骗子的说法，所以第二条通道交给模型，但给了它硬约束：

1. 只能从既有特征分类表中选择，不得自创类别 → 法规引证依然成立
2. 必须给出原文中真实存在的引文，引不上直接丢弃，丢弃了哪几条会列给用户看
3. 引文要过与规则通道完全相同的否定 / 科普语境检查
4. 硬性违规只接受高置信度；模型自称没把握的丢弃
5. 规则通道已解释过的文本片段，语义通道不再插话

**风险定级。** 由命中项的类型与数量确定性地算出，不经过模型。硬性违规命中即进入最高档，高风险诱导按数量累计。

**五维风险画像。** 把散落的命中项收敛成五个维度（收益承诺、资质可核验、渠道正规、紧迫压迫、情感操控），纯确定性计算。

**财务计算。** 分期真实年化用 IRR 数值求解，应急金按支出与收入稳定性算月数。都是封闭形式或数值迭代，可单测、可复现。

### 6. 数据库与数据处理方案

**不建数据库，这是刻意的选择。**

| 数据 | 存在哪 | 为什么 |
|---|---|---|
| 知识库（违规话术特征、法规条文、术语表、骗局图鉴、投资方向、陷阱提醒、市场基准、题库、演示样本） | 仓库里的 JSON 文件，共 9 份 | 可版本控制、可 diff、可追溯到某次修改。每条法规带核对状态与来源链接，评审可当场核对 |
| 用户画像 | 用户自己浏览器的 localStorage | 金融场景下不建集中式用户库，就没有泄露面。读写全部 try/catch，损坏时退回空档案 |
| 公开行情 | 不落库，服务端按需拉取，标注来源与时间 | 不存快照就不会出现「展示过期数据」 |

**数据处理纪律**（写在项目宪法里，也写进了数据文件本身）：

- 法规条文没核对官方原文的，只显示要义概述并标注「条文原文待核对」，不自己填原文。目前 14 条全部已核对。
- 市场基准数据只填能查到出处的。填不到就留 `null`，前端自动改用定性表述，不显示空值，并在数据文件里写明为什么填不到。
- 案例字段只放真实公开报道，来源域名必须是 gov.cn。宁可留空。
- 演示样本一律自制仿真，机构名虚构，不用能认出真实公司的截图。

### 7. 前后端实现方案

**服务端。** 四个 Route Handler：风险体检、条款翻译、识别测试判定、公开行情。体检接口返回 SSE 流，按阶段推送 `start / progress / done` 事件，命中项逐条推送，前端逐条点亮。心跳节奏是刻意留的：让用户看清每一步在做什么，而不是转三秒圈然后甩出一个结论。

**客户端。** 页面组件订阅事件流，增量渲染进度与命中项，最后收到完整报告对象再整体渲染。图片在浏览器端先等比压缩到长边 1600px 再转 dataURL 上传，省流量也省模型耗时。

**降级。** 视觉识别失败退回纯文本路径；语义通道 7 秒超时退回纯规则；模型转述 8 秒硬超时退回模板；无 API key 时整条链路走本地 mock。任何一环失败都不影响出结论。

**类型契约。** 报告结构定义在 `lib/types.ts`，前后端共用，改字段两端一起报错。

### 8. 安全性、稳定性、合规性设计

**安全。**

- 用户画像不上传、不建集中用户库
- 进模型前先脱敏，去掉手机号等个人信息
- 模型输出中出现 6 位股票代码、基金代码、产品全称一律脱敏
- 不引用任何外链资源，没有第三方脚本，没有埋点 SDK

**稳定。**

- 每一步都有超时与兜底，见 §7
- 无 key 可完整演示，断网可演示
- 843 项断言的回归测试，每次改规则库必须全绿
- 现场演示不依赖外网模型也能跑通

**合规。** 判断标准很简单：**推荐具体标的属于证券投资咨询业务，要牌照；风险提示和投教是监管鼓励的。** 我们没有牌照，所以划了三条线。

| | 我们的做法 |
|---|---|
| 绝对不做 | 推荐具体股票、基金、理财产品，连举例都不行。不预测涨跌，不承诺收益，不代客理财，不宣传预期收益率，不对广告作「是否诈骗」的法律定性 |
| 谨慎做 | 大类资产配置只讲思路和比例原则。适当性匹配意见要同时声明「这不构成对产品风险收益的实质判断」 |
| 放心做 | 术语与条款翻译、广告风险体检、风险提示与投教、引用监管公开信息并标注来源 |

措辞规范落到每一句文案上：

| 不能说 | 我们说 |
|---|---|
| 这是诈骗 | 这段内容命中了 N 条监管明令禁止的表述特征 |
| 这个产品安全 | 没有识别到违规表述特征。这不构成对这个产品的安全性保证 |
| 建议配置 20% 股票基金 | 权益类参考比例 20% |

这些规范不是靠自觉，是靠 `lib/rules/guard.ts` 里的确定性代码强制执行的，六类越界表述硬拦截：投资建议、涨跌预测、安全保证、诈骗定性、合规定性、可信度评价。每个功能页底部强制带免责声明，关不掉。

我们反复说的一句话是：**我们只能检查它说了什么，检查不了它实际做什么。** 所以主体核查只给官方查询入口，让用户自己去证监会、基金业协会、国家企业信用信息公示系统查。我们不代替官方下结论，也不把查询结果存下来说「已认证」。

### 9. 技术难点与解决方案

**难点一：关键词库永远穷举不完。**

内部测试输入「把钱全给我，我一定帮你炒股赚大钱」，第一版判成绿色。这句话同时踩了代客理财和收益承诺两条硬红线。原因是特征库当初照着正规广告文案建的，收的是「保本保息」「预期年化收益」这类书面词；真实骗局在微信里说的是大白话。补几个关键词治不好——骗子的说法无穷多。

解法是加第二条语义通道，但用四条硬约束把它锁住（见 §4）。**规则通道保证说出来的都是对的，语义通道保证该发现的不漏掉。**

**难点二：模型会自己补事实。**

接入真实模型后，有个模型在总结里写了一句「银行大额存单才 2% 左右」。这个数字原文里没有，我们的判定里也没有。它可能是对的，但我们没法核实，一旦被追问就是硬伤。

解法是编造数字检测：把模型输出里的数字和原文比一遍，只要出现原文里没有的数值，整段丢弃、退回模板。另外，风险最低那一档（「暂未发现明显问题」）干脆不让模型开口，只用逐字审过的模板——实测发现模型在这一档最爱下结论，写出过「它没有违反金融监管规定」这种我们无权说的话。

**同一类问题的另一个变种：模型自己说和模型引用原文，措辞尺度不一样。** 规划师问答实测中，模型讲还债省利息时写成「每还掉一元就等于白赚 13.03%」——数学上站得住，但「白赚」是承诺式措辞，我们无权说。可是把这个词一律拦掉又不行：模型转述广告原文「他说稳赚不赔」是正确引用，改了就失真。

解法是让审查层区分**谁在说**：「白赚 / 净赚 / 躺赚 / 稳赚 / 包赚 / 准赚 / 轻松赚 / 闭眼赚」这 8 个词，未被引号包裹时拦截，紧邻字符是引号时放行。判据简单，但它把「合规」和「忠实转述」这两个互相拉扯的要求同时满足了。

**难点三：误判比漏判更致命。**

把正规产品判成骗局，摧毁的是产品本身的可信度。现场演示时一次误判比没有 demo 更糟。

解法是三层确定性排除（否定语境、科普语境、术语白名单）加一条纪律：用一份四项要素齐备的正规产品材料做反向对照样本，纳入回归测试，每次改规则库都必须验证它仍判绿。这条纪律先后抓出四类误判：「固定收益类」被判违规、「无风险利率」被判违规、反诈科普句被判高风险、资金盘判级过低。

**难点四：适老化的字号开关按下去没反应。**

第一版用 `body` 上的 `font-size` 做放大，实测按下开关几乎看不出变化。原因是全站有四百多处把字号写死在元素上（`text-[13px]` 这类），元素自身的 `font-size` 优先级更高，改 `body` 压不动它。

解法是改用 `zoom`：它触发整体重排，写死的 px 也跟着放大，等价于浏览器自身的缩放，流式容器会自适应，不会像 `transform: scale` 那样撑出横向滚动。在此基础上做成百分比调节（100%–160%）并给四档预设，偏好存本地，任何一页刷新后都保持。

> 这个坑值得单独写出来，因为它说明适老化不是「加个开关」就完了——不实际拿大字号走一遍全站，根本发现不了开关是失效的。

**难点五：同一输入结果不稳定。**

同一段文字连跑三次，第三次模型把「保本保息」错标成「混淆存款与理财」——而该片段规则通道已正确解释过。解法是明确两条通道的分工优先级：规则通道已解释过的片段，语义通道不再插话。修正后同一输入连跑 5 次结果完全一致，而口语召回一条未丢。

## 七、应用场景

### 1. 零基础理财科普咨询场景

**谁**：刚开始接触理财的人，看不懂术语、分不清基础产品类型、有疑问没人问。

**怎么用**：把看不懂的产品说明书或者广告拍下来传进来，先翻成大白话，再看有没有风险。术语点开就地解释，看完顺手去闯关把这一类知识补上。

**我们的边界**：只做知识与条款的通俗化解读，不评价任何产品好坏。

### 2. 低风险理财决策辅助场景

**谁**：自主理财时纠结、容易跟风、风险意识薄弱的普通用户。

**怎么用**：先做风险测评拿到风险画像，系统会指出回答里的自相矛盾；再看品类优先级（有高息负债先还债、没应急金先攒应急金），然后看大类比例原则。想看市场就看 12 个方向的近 60 日走势、区间涨跌和振幅——固定顺序、不排名，涨跌和波动同时给出。

**我们的边界**：只输出风险画像、大类比例原则和公开数据的客观陈列。**不做行情解读结论，不给个性化的产品建议，不指向任何具体标的。**

### 3. 个人轻量化资产管理场景

**谁**：有小额资产和日常收支、想理清家底的普通个人。

**怎么用**：应急金计算器算出该留几个月，分期计算器算出手上那笔分期的真实年化成本，品类优先级给出「先做什么后做什么」的 6 步顺序，每步带「做完的标准」，用户知道自己走到哪一步了。

**我们的边界**：纯计算与顺序排列。只排顺序，不排产品。

### 4. 社区与机构的反诈宣传落地场景（本项目新增）

**谁**：社区、街道、老年大学、银行网点、高校。

**怎么用**：现场摆一台设备当反诈体验终端，居民把手机里收到的广告传上去，当场看到命中了哪几条、依据哪条法规。活动结束能导出参与人数、常见命中类型的统计，作为履职留痕材料。

**为什么这个场景重要**：养老诈骗案件里非法集资约占六成，北京市数据里 60 岁以上受害人占二成。老年人不会自己下载一个防骗 App，但「子女帮父母查」和「社区活动现场当体验终端」这两条路是通的。这也是我们的第一批付费客户所在的场景。

## 八、核心创新点

### 1. 普惠型金融科普：注重教育与防范，不是投资推荐

绝大多数金融 AI 产品在回答「买什么」。我们回答「这句话为什么不能信」。

前者需要牌照，服务的是已经有基础、想提高收益的人；后者是监管明确鼓励的投资者保护与投教，服务的是最容易亏掉本金的人。**对一个刚开始理财的人来说，躲开一次五万块的骗局，比多赚百分之五重要得多。**

### 2. 一站式降低入门门槛：短平快，不用先学完再理财

信息辨别、知识普及、理财分析打包在一个入口里，覆盖金融小白的全流程成长。

针对的是一个很具体的错配：**大多数人是在遇到某个理财产品的那一刻才需要金融知识的，而那一刻他既没有时间、也没有渠道去系统学习。** 传统投教按知识体系组织内容，要求用户先学完再使用；我们反过来，把学习入口放在他正需要判断的那一刻——

- 传一张截图，三秒出结果，不用先读完一本书
- 报告里看不懂的术语点开就地解释，不用跳走
- 看完顺手去闯关把这一类知识补上，答错就地讲清

**「开始」这件事被做得足够容易，门槛就降下来了。**

### 3. 个人用户档案动态更新：从零开始培育长期用户

信息辨别、题目学习、风险偏好、个人收支共同构成用户画像，动态更新，反映用户的成长变化。三个入口共读共写同一份档案，形成真实联动（见 §五.3）。

两条纪律让这个联动不是噱头：**每条定向提示都带来源行**（「依据：规划师测出你的风险偏好偏进取」），可以被用户当场验证；**档案为空时一条都不出**，不虚报联动。

档案只存在用户自己的浏览器里，不上传、不建集中式用户库。**在金融场景下，这是刻意的隐私选择。**

### 4. 信息集成：打破碎片化，把检索成本降到零

同一个概念在不同平台说法不一，用户要自己拼凑。我们把散落各处的东西集成到「一次判断」里：术语解释、法规原文、骗局套路、官方查询入口、公开市场数据，全部在报告里直接给出，不用用户自己去搜。

**关键是这些集成内容都可溯源**：法规带来源链接和核对状态，案例带 gov.cn 页面链接，市场数据带来源与日期。集成不等于把信息揉成一锅，而是把它们按「此刻要做的判断」重新组织，并保留每一条的出处。

### 5. 适老化不是装饰，是核心功能

全站字号百分比调节（100%–160%，另给「标准 / 大 / 更大 / 最大」四档预设，给不想拖滑块的人一步到位）、术语按档案年龄段自动简化、骗局图鉴按人群重排、支持子女代查。

依据是养老诈骗案件里非法集资约占六成、北京市数据里 60 岁以上受害人占二成的现实。**这个人群是产品的主要服务对象，不是无障碍清单上的一个勾。**

### 6. 选题：把合规约束反转成护城河

在现行监管下，未持牌推荐具体股票、基金、理财产品属于非法证券活动。所有走「帮你赚钱」路线的 AI 金融产品，天花板都被合规按住了——做得越具体、越有用，越难解释怎么合法运营。

我们反过来选：投资者教育与反非法金融活动宣传，是《证券法》《反电信网络诈骗法》和各级监管部门明确要求金融机构履行的义务。**同样一件事，别人做要牌照，我们做是监管鼓励。** 合规不是成本，是护城河。

### 7. 架构：判断不交给模型，且模型输出可验证

风险等级、命中项、法规依据全部由确定性代码产生，模型只负责认字和讲人话。带来三个可验证的性质：

- 换模型不改变判定结果 → 可按机构合规要求私有化部署、可换国产或自有模型
- 每条结论可溯源到法规原文 → 用户点开就看到依据的是哪一条
- 模型说错了也不影响结论 → 三道防线全部是确定性代码：语义通道的四条硬约束、输出审查层的六类拦截加编造数字检测、超时降级与最低风险档只用模板

语义校验层有 11 例单元测试，用假 provider 专门喂「模型可能给出的坏输出」：引文改写、自创类别、低置信度、处于否定或科普语境、与规则通道同片段但标了别的特征、非 JSON 输出——全部丢弃或安全降级。

这样「AI 会不会乱说」就不再是一个需要用户信任的问题，而是架构上已经定下来的事。

### 8. 误判防护：我们认为误判比漏判更致命

把正规产品判成骗局，摧毁的是产品本身的可信度。三层确定性排除（否定语境、科普语境、术语白名单）加一份四要素齐备的正规产品反向对照样本，纳入回归测试，改规则库必验。这条纪律先后抓出四类误判。

**方法论上这是把「不误判」当成一等公民**，而不是准确率里的一个分母。

### 9. 骗局剧本预测与 AI 主动追问：从判断现状到指向下一步

识别出骗局类型后不只说「这有问题」，而是按推进顺序告诉用户对方接下来会做什么：先让你小额提现一次尝到甜头 → 展示别人的收益截图制造从众 → 劝你加大投入并拉亲友 → 某天系统「升级维护」提现开始延迟 → 要求先交解冻金 → 客服失联。9 类骗局、48 步剧本。

**为什么这比警告有效**：它是一个可被用户自己验证的预测。用户不需要相信我们，只需要等着看对不对，而每一步被印证都在加强他退出的决心。现实依据是北京市公安局数据里的平均 36.7 天成案时间——存在一个月的窗口期，来得及拦。

配套的是主动追问：系统先判断自己缺什么信息，再决定要不要问、问什么，信息足够时一个都不问；用户的回答被拼回原文重跑一遍完整分析。**同一份广告，对「还没转钱的人」和「已经被要求交解冻金的人」，最该说的话完全不同。**

### 10. 把「不给建议」变成教育契机

用户问「某只基金怎么样」「买哪个好」，我们不是含糊其辞地绕过去，而是明确拒答并把话说透：这属于持牌业务，我们没牌照，做了就违规，而一个越界的建议对你本身也不安全。紧接着给出能替他做的三件事——把条款翻成人话、比对宣传里有没有违规表述、告诉他去哪里核验资质编号。

这条路径是有代码的，不是文案姿态：5 类越界意图由规则层的意图闸门在模型之前拦下，走的是逐字审过的模板，模型根本不参与。

规划师其余部分同理——不给「买什么」，而给「先做什么后做什么」：6 步品类优先级，每步带「做完的标准」。方向看板也是同一个思路，不告诉用户买哪个，而是把涨跌和振幅并排放在一起，让他自己看到收益和波动是一起来的。

**这些都是纯事实与顺序，完全合规，但它们做的正是投顾真正该做的事。** 而且拒答那一段本身就是最好的投教——用户第一次知道「原来给我推荐股票的人是违规的」。

### 11. 把「较真」做成了功能

- **14 条法规逐条核对官方原文并附链接**，核对过程记在 `docs/legal-check.md`，过程中查出并改正 3 处错误，其中一处引的是修正案之前已废止的旧条文
- **10 条骗局案例全部出自 gov.cn 官方页面**，链接逐条验证可打开，引文逐字复核，企业名与个人姓名一律「某」字化——我们展示骗局怎么运作，不是曝光名单
- **查不到就留空**：市场基准填不到官方出处的保持空值，前端自动改用定性表述，并在数据文件里写明为什么填不到

这一条看起来不像创新，但它是前面十条的地基：**只要有一处编造被问穿，整个知识库的可信度就一起没了。**

## 九、实际价值

### 1. 用户价值

| 价值 | 说明 |
|---|---|
| 少亏钱 | 直接对应单笔损失最大的一类骗局。北京市数据里这类案件占案子的 7%、占被骗金额的 38% |
| 看得懂 | 术语与条款当场翻译，不必先学完再理财 |
| 有依据 | 每条结论都能点开看法规原文和来源链接，不是「AI 说的」 |
| 知道下一步 | 骗局剧本给出可验证的预测，比「请提高警惕」有用 |
| 隐私 | 画像只存在自己浏览器里，不上传 |

### 2. 社会价值

投资理财类骗局是最高检点名的重点领域之一、公安部十类高发之一，单笔损失最大、成案周期最长。我们把干预插进那 36.7 天的窗口期。

同时补的是普惠金融教育的缺口：把学习入口放在用户正需要判断的那一刻，触达的正是最需要、却最难被投教覆盖的人群——中老年人、学历不高的普通劳动者、刚有闲钱的大学生。

### 3. 行业价值

投资者适当性管理、投教、反非法金融活动宣传是机构的硬性义务，现在多靠传单、海报、讲座完成，效果难考核、难留痕。我们提供可统计、可留痕、可白牌部署的替代手段。

对行业更长远的价值是：**证明「不推荐标的」也能做出有用的金融 AI 产品**。这条路能走通，会有更多团队愿意在合规区内做事。

### 4. 技术价值

- 一套可复用的**「判定归规则、转述归模型」范式**：在容错率极低的场景里，把模型限制在它可靠的环节上，其余交给确定性代码
- 一套可复用的**双通道设计**：规则保精度、模型保召回，共用一套排除标准，并明确优先级避免互相污染
- 一套可复用的**输出审查方法**：越界表述拦截 + 编造数字检测，比调提示词可靠
- 一套可核查的**知识库工程纪律**：核对状态入库、来源链接入库、查不到就留空并写明原因

## 十、商业落地路径

### 1. 目标用户与市场分析

**个人端三类人**，共同特征是有钱、辨别力弱、经常接触到理财广告：

| 人群 | 特征 | 触达方式 |
|---|---|---|
| 领退休金的老年人 | 有积蓄，辨别能力较弱，在互联网上频繁接触理财广告。养老诈骗里非法集资约占六成 | 社区活动现场体验终端、子女代查 |
| 教育水平较低的普通劳动者 | 有积蓄，缺少系统学习的时间和渠道 | 短视频与本地生活平台内容分发 |
| 手里有闲钱的大学生 | 刚开始理财，容易被高收益话术和校园贷吸引 | 高校财商课程、社团活动 |

**机构端是付费方**：银行与券商（适当性管理与投教是硬性义务）、社区与街道（反诈宣传年年有预算）、高校（财商教育与防范校园贷进课表）。

**市场判断**：这不是创造新需求，是替代现在效果不好的办法。投教与反非法金融活动宣传是监管要求的、有明确预算科目的刚性支出，替代的对象是传单、海报和讲座。

### 2. 商业模式设计

**机构付费，个人免费。**

为什么不做个人订阅：人们会系统性低估自己被骗的概率，为「防骗」付钱的意愿很低。而机构那边是合规驱动的刚性支出，谁做决定、钱从哪出，都是清楚的。

个人免费还顺手解决了两件事——分发和样本。

```
个人用户传上来可疑广告
  → 沉淀真实的骗局样本和新话术
  → 规则库和特征库跟着更新
  → 识别得更准
  → 机构那边的产品更有竞争力
  → 有收入，再投回内容和技术
```

个人免费不是补贴换增长，是换样本。骗子的话术每周都在变，只有真实的上传量能让规则库跟上。

### 3. 落地实施步骤

| 阶段 | 做什么 | 验证什么 |
|---|---|---|
| 短期（0–6 个月） | 完成个人端上线；在 1–2 个社区和 1 所高校做落地试点，现场当反诈体验终端用 | 真实用户能不能自己走完一次体检；识别准确度在真实样本上的表现；活动数据能不能满足机构的留痕需求 |
| 中期（6–18 个月） | 签下第一批机构客户（社区 / 高校优先，采购流程短）；把活动包、课程包、数据看板产品化；建立话术库的周更新机制 | 单个机构客户的交付成本；续约率；规则库更新速度能不能跟上话术变化 |
| 长期（18 个月以上） | 面向银行、券商提供白牌工具与适当性匹配辅助，支持私有化部署；沉淀话术库对外提供数据服务 | 能不能通过机构的合规与信息安全评审；私有化部署的边际成本 |

**私有化部署可行的原因**：判定归规则，换模型不改变结论。机构可以把模型换成自己的，判定逻辑照旧。

### 4. 推广与运营方案

| 渠道 | 做法 |
|---|---|
| 社区与老年大学 | 反诈活动现场设体验终端，工作人员协助，活动后出统计报告 |
| 高校 | 财商课程包 + 闯关系统 + 班级数据看板，配合防范校园贷宣传 |
| 银行网点 | 白牌工具嵌入现有投教专区，作为适当性管理的辅助留痕手段 |
| 内容分发 | 骗局图鉴与定向微课本身就是内容资产，适合在短视频与本地生活平台做拆解式科普 |
| 口碑 | 「子女帮父母查」是最自然的传播链，产品的分享深链就是为这个设计的 |

运营上的一条纪律：**永远不做「已认证」「安全」这类背书式表述。** 我们的可信度建立在「每条结论都能点开看依据」上，一旦开始做背书，这条护城河就自己填了。

### 5. 盈利模式

| 客户 | 为什么会付钱 | 卖什么 | 优先级 |
|---|---|---|---|
| 银行、券商 | 投资者适当性管理和投教是硬性义务，要留痕、要能考核 | 白牌工具、投教活动数据报告、适当性匹配辅助、私有化部署 | 高 |
| 社区、街道、老年大学 | 反诈宣传年年有预算，现有手段效果差 | 反诈体验终端、活动包、效果报告 | 高 |
| 高校 | 财商教育与防范校园贷要进课表 | 课程包、闯关系统、班级数据看板 | 中 |
| 个人 | 免费 | 流量入口，同时带回真实样本 | — |

### 6. 竞品对比与核心竞争力

| | 国家反诈中心 App | 各类投教平台 | AI 投顾类产品 | 财智通 |
|---|---|---|---|---|
| 作用层 | 通讯与交易层拦截 | 知识供给 | 决策建议 | **内容层的合规体检** |
| 面对的对象 | 已发生的接触行为 | 愿意主动学习的人 | 有一定基础、想提升收益的人 | **手里正拿着一张可疑广告的人** |
| 能否处理一张群聊截图 | 不能 | 不能 | 不能 | **能，并给出法规依据与核查指引** |
| 牌照要求 | 官方主体 | 无 | **推荐具体标的需持牌** | 无（不做需持牌的部分） |
| 结论可溯源 | — | — | 通常不可 | **每条命中可追到原文与法条** |

**核心竞争力三条**：

1. **合规定位本身**。竞争者要牌照，我们不要。这不是一时的领先，是结构性的。
2. **可核查性**。14 条法规核对官方原文、10 条案例出自 gov.cn、843 项断言、判定不经过模型。这些东西是机构合规评审真正会问的，也是最难在短时间里补齐的。
3. **样本飞轮**。个人免费带回真实话术，规则库周更新，机构产品因此更准。

> 北京市公安局的数据显示，虚假网络投资理财类受害者中「多数有专业投资理财经历」。这一句直接推翻了「理财小白才被骗」的假设，也说明单靠知识供给救不了他们——他们不缺知识，缺的是在那 36.7 天窗口期里，一个可核验、指向具体条文的判断依据。**这就是我们和所有投教类产品的分界线。**

## 十一、可行性分析

### 1. 技术可行性

已经跑通，不是设想。

| 证据 | 状态 |
|---|---|
| 四个功能入口 | 已上线可用 |
| 六阶段流水线 | 已实现，SSE 流式。只翻译不到 1 秒，文字体检 4–5 秒，图片体检约 8 秒 |
| 自动化测试 | 843 项断言全绿 |
| 知识库 | 9 份 JSON，15 类特征 / 365 关键词 / 14 条法规 / 9 类骗局 48 步剧本 / 24 条术语 / 25 道闯关题 / 16 条微课 |
| 无网络降级 | 无 API key 时本地 mock 完整演示 |
| 换模型 | 走统一适配层，判定不受影响 |

技术上没有需要突破的前沿问题——难点在工程纪律，而纪律已经被写成测试和代码约束固定下来了。

### 2. 市场可行性

需求是官方点名的（最高检重点领域、公安部十类高发之一），付费方的预算科目是现成的（投教与反诈宣传是监管硬性要求），替代的对象是效果可考核性很差的传单与讲座。

短期最容易落地的是社区与高校：采购流程短、决策链短、效果验收标准简单（参与人数、活动统计）。银行与券商价值更高但评审周期长，放在中长期。

### 3. 运营可行性

- **交付轻**：网页应用，扫码即用，不用装、不用配置，现场一台设备就能当终端
- **内容可复用**：骗局图鉴、微课、题库既是产品功能，也是活动物料和分发内容
- **人力可控**：核心运营工作是话术库更新——把用户上传的新话术归类进 15 个既有特征里，是有明确流程的重复劳动，可以标准化

### 4. 合规可行性

这是我们最有把握的一项，因为整个产品是围绕它设计的，不是事后补的。

| 合规要求 | 我们的应对 |
|---|---|
| 不得未持牌从事证券投资咨询 | 不推荐任何具体标的，连举例都不行；不预测涨跌，不给买卖点 |
| 不得承诺或暗示收益 | 收益率假设由用户自己给；不宣传预期收益率 |
| 不得对他人作法律定性 | 只说「命中 N 条监管明令禁止的表述特征」，不说「这是诈骗」 |
| 不得虚假宣传、不得为机构背书 | 不说「安全」「可靠」「正规」「已认证」；主体核查只给官方查询入口 |
| 引用须有据 | 法规带核对状态与来源链接；查不到的留空并写明原因 |
| 个人信息保护 | 画像不上传、不建集中用户库；进模型前脱敏 |
| 名誉风险 | 演示样本全部自制仿真，机构名虚构；案例里的企业名与个人姓名脱敏 |

这些不是承诺，是代码约束：六类越界表述由 `guard.ts` 硬拦截，免责声明强制渲染且关不掉。

## 十二、风险分析与应对方案

### 1. 技术风险

| 风险 | 应对 |
|---|---|
| 模型不可用、超时或返回垃圾 | 每一步都有超时与兜底：视觉失败退纯文本、语义超时退纯规则、转述超时退模板、无 key 退 mock。任何一环失败都不影响出结论 |
| 模型幻觉写出无法核实的内容 | 输出审查层：六类越界表述拦截 + 编造数字整段作废；最低风险档不让模型开口 |
| 新话术漏判 | 双通道设计 + 用户上传样本驱动的规则库周更新机制 |
| 误判正规产品 | 三层语境排除 + 正规产品反向对照样本纳入回归测试，改规则库必验 |
| 结果不稳定 | 判定全部由确定性代码产生；两条通道明确优先级，同一输入连跑 5 次结果一致 |
| 行情接口不可用 | 公开指数数据取不到时前端显示为空并说明，不落库、不展示过期数据 |

### 2. 市场风险

| 风险 | 应对 |
|---|---|
| 个人用户为「防骗」付费意愿低 | 个人端本来就免费，收入来自机构。个人端的作用是分发与样本 |
| 机构采购周期长 | 先攻采购流程短的社区与高校，用真实活动数据去谈银行与券商 |
| 官方工具功能扩展，覆盖内容层 | 我们的价值在法规引证、投教联动与可核查性，与官方工具是互补关系；且我们可以白牌输出给机构，这是官方工具不做的事 |
| 大厂进入 | 大厂做「帮你赚钱」的动力远大于「帮你不被骗」，且持牌主体做投顾的收益更高。这个细分市场对它们不够大 |

### 3. 数据与合规风险

| 风险 | 应对 |
|---|---|
| 被指「无牌照从事投资咨询」 | 产品从设计上不含任何需持牌的功能，见 §十一.4 |
| 被指「对他人作法律定性」造成名誉损害 | 只输出表述特征命中，不作定性；演示样本全部自制仿真，机构名虚构 |
| 用户上传内容含个人信息 | 进模型前脱敏；画像只存本地；不建集中用户库 |
| 引用的法规过期或条号错误 | 逐条核对官方原文并记录核对过程；已查出并改正 3 处错误，其中一处是修正案之前的废止文本 |
| 编造数据 | 项目纪律：查不到就留空并写明原因。法规原文未核对的只显示要义并标注；市场数据填不到就 `null`，前端自动改用定性表述 |
| 用户把「绿色」当成安全保证 | 绿色档只用逐字审过的模板，明确写「没有识别到违规表述特征，这不构成对该产品的安全性保证」；反复强调「我们只能检查它说了什么，检查不了它实际做什么」 |

### 4. 运营风险

| 风险 | 应对 |
|---|---|
| 话术库更新跟不上 | 把归类流程标准化（新话术归入 15 个既有特征），使更新成为可重复的日常工作而非研发任务 |
| 老年用户不会用 | 字号百分比调节 + 四档预设、术语自动简化、社区现场有人协助、支持子女代查 |
| 现场演示出问题 | 无 key 本地 mock 可完整演示，断网可演示；不引任何外链资源，首屏不依赖外网 |
| 用户过度依赖，放松警惕 | 产品文案明确写「我们不是唯一的防线，也不该是」，并列出我们不做什么 |
