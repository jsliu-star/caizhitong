## 1. 🔴 查出的错误与改正（重点看这一节）

### 错误 1（条号错）：《证券法》第一百六十条 ≠ 代客投资禁止

- **原文件写法**：`reg-securities-160`，`article: "第一百六十条"`，
  gist 为「从事证券投资咨询业务的机构及其从业人员，不得代理委托人从事证券投资，不得与委托人约定分享投资收益或分担投资损失，不得买卖本机构提供服务的证券。」
- **错在哪**：这段内容在现行《证券法》（2019 年 12 月 28 日第二次修订）里是**第一百六十一条**，不是第一百六十条。
  第一百六十条的实际内容是证券服务机构的勤勉尽责义务，以及**投资咨询服务业务的核准要求**：
  「从事证券投资咨询服务业务，应当经国务院证券监督管理机构核准；未经核准，不得为证券的交易及相关活动提供服务。」
- **怎么改的**：
  - `reg-securities-160` 的 **id 保持不动**（`data/violation-patterns.json` 与 `app/api/shield/route.ts` 在引用它），
    但把 `article` / `gist` / `officialText` 改成**第一百六十条的真实内容**（＝投资咨询须核准）。
    这样 id 里的「160」和条号正好对得上。
  - **新增** `reg-securities-161` 承载第一百六十一条（代客投资 / 约定分享收益 / 买卖本机构服务证券的禁止）。
- **为什么这样改而不是直接把 160 改成 161**：`reg-securities-160` 这个 id 被两个不属于任务 D 的文件引用，
  改 id 会造成悬空引用；而且拆成两条之后，「无证荐股」引第一百六十条（牌照）、「代客理财」引第一百六十一条（代客禁止），
  法条依据反而比原来更精准。
- **已协调**：任务 A（ai-c3）已在 `data/violation-patterns.json` 为
  `vp-discretionary-trading` 与 `vp-stock-recommendation` 补上 `reg-securities-161` 引用，
  并已跑过悬空引用检查（零悬空）+ 全套测试。
- **独立复核**：任务 A 在收到通知前**已独立从《证券法》全文查到同一处错误，结论完全一致**。
  两条独立路径得到同一结果，这处修正可以放心用。

### 错误 2（要义概述错）：《理财公司理财产品销售管理暂行办法》第二十五条没有「业绩最佳」「规模最大」

- **原文件写法**：gist 称该条「禁止使用『业绩最佳』『规模最大』等夸大性表述」。
- **错在哪**：**该条原文中没有这两个词。** 第二十五条是一份十八项的禁止清单，
  逐字核对后与我们产品相关的实际禁止项是：
  （一）误导投资者购买与其风险承受能力不相匹配的理财产品；
  （二）虚假宣传、片面或者不当宣传，夸大过往业绩，预测理财产品的投资业绩，或者出具、宣传理财产品预期收益率；
  （四）将销售的理财产品与存款或其他产品进行混同；
  （九）为理财产品提供直接或间接、显性或隐性担保，包括部分或全部承诺本金或收益保障。
- **怎么改的**：删掉「业绩最佳／规模最大」，gist 改写为上述四项的概述，`officialText` 抄录引导句 +
  第（一）（二）（三）（四）（九）（十八）项，省略项以「……」标注。
- **附带好处**：第（四）项「与存款或其他产品进行混同」正好是 `vp-deposit-confusion` 这一类特征的精准依据，
  覆盖面比原来那句错的更广。

### 错误 3（要义概述错）：刑法第二百六十六条原文不含「虚构事实、隐瞒真相」

- **原文件写法**：gist 为「以虚构事实或隐瞒真相的方法骗取公私财物，数额较大的，构成诈骗罪。」
- **错在哪**：「虚构事实、隐瞒真相」是刑法理论与司法解释里的表述，**法条原文里没有这六个字**。
  第二百六十六条原文是「诈骗公私财物，数额较大的，处三年以下有期徒刑……」，直接以「诈骗」为构成要件用语。
  这是一个很典型的错误——大量二手资料都这么写。
- **怎么改的**：gist 改为按数额与情节分三档量刑的faithful概述，`officialText` 抄录原文全文。

### 附带修正（不算错，但原表述不够准确）

**`reg-securities-120`**：原 gist 称「从事证券投资咨询等证券业务须经核准……未经许可不得从事相关证券业务活动」。
后半句对第一百二十条来说**过宽**：该条第四款的禁止清单是「证券承销、证券保荐、证券经纪和证券融资融券」，
**不含投资咨询**。已在 gist 中加括号注明这一点，并指明「未经核准不得从事投资咨询服务业务」的依据在第一百六十条第二款。
这个区分在答辩时可能被懂法的评委追问，写清楚更稳。

### 🔴 版本陷阱（这条最值得记住）

**刑法第一百七十六条：几乎所有二手资料给的都是 2021 年前的旧文本。**

搜索引擎返回的、以及最高人民法院公报网站上的《刑法》全文，都是 **1997 年修订版**，
其第一百七十六条写的是「并处或者单处**二万元以上二十万元以下**罚金；数额巨大或者有其他严重情节的，
处三年以上十年以下有期徒刑，并处**五万元以上五十万元以下**罚金」——**这是已被修改的旧条文**。

刑法修正案（十一）对该条作了三处实质修改：
1. 删除了具体罚金数额，改为「并处或者单处罚金」；
2. **新增第三档**「数额特别巨大或者有其他特别严重情节的，处十年以上有期徒刑，并处罚金」；
3. 新增第三款「有前两款行为，在提起公诉前积极退赃退赔，减少损害结果发生的，可以从轻或者减轻处罚」。

因此本条 `officialText` 直接取自**中国人大网《刑法修正案（十一）》原文**，
并在 `sourceName` 中注明「本条现行文本即由该修正案确定」。

**如果我们照抄公报里的 1997 年文本，答辩时被懂法的评委指出「你引的是废止条文」，
整个法规库的可信度就一起归零了。** 这是本次核对最大的收获。

同理，`reg-criminal-224a`（第二百二十四条之一）在 1997 年文本里**根本不存在**，
它是刑法修正案（七）增设的，所以只能引修正案原文。

## 4. 检索方法与踩过的坑

**结论：搜索引擎摘要一律不可作为法条依据，必须打开原页面逐字读。**

本次核对中，检索摘要出现的错误：

| 摘要说法 | 实际 |
|---|---|
| 《证券法》代客投资禁止在第一百六十条 | 在**第一百六十一条** |
| 刑法第一百七十六条（给出含具体罚金数额的文本） | 那是**修正案（十一）之前的废止文本** |
| 《防范和处置非法集资条例》广告禁止在第九条 | 在**第十一条** |
| 《防范和处置非法集资条例》第八条＝禁止宣传推介 | 第八条是**监测预警机制** |

**可用的操作方式**（本机实测可直连国内政府站点）：

```bash
curl -sSL --max-time 40 -A "Mozilla/5.0" "<官方页面>" -o x.html
# 再用一个去 HTML 标签的小脚本转成纯文本，自己 grep 条号、自己读
```

这样看到的是**原始字符**，不经任何模型转述。
`WebFetch` 这类「抓取后由小模型作答」的工具在此类任务上不可靠——它会转述、会截断、会漏掉分项。

**各来源可达性实测**（2026-09-07）：

| 站点 | 可达性 |
|---|---|

| `npc.gov.cn`（中国人大网） | ✅ |
| `policy.mofcom.gov.cn`（商务部全球法规网） | ✅ 部门规章在这里最好找 |

## 5. 对 `data/regulations.json` 结构的改动

为每个条目**新增两个字段**（14 条全部都有，结构保持同构）：

- `sourceName`：来源名称 + 版本与效力信息（含发布机关、令号、施行日期）
- `sourceUrl`：**实际抄录的那个页面**的地址

同时更新了 `_note`（说明「……」省略标注规则）、`version`（0.1 → 1.0）、
`lookupUrls`（补入国家法律法规数据库、中国政府网、国家金融监督管理总局）。

`lib/types.ts` 的 `Regulation` 接口**未改动**（它是共享基础设施，任务 D 只读）。
`app/api/shield/route.ts` 用的是 `as Regulation[]` 类型断言，多出的字段不影响编译；
已跑 `npm run build` 确认通过。前端 `components/shield/Report.tsx` 不读这两个新字段，
展示逻辑不变——`verified: true` 后会显示「原文已核对」徽标并展示 `officialText`。
