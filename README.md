## 架构要点

```
用户输入（图片 / 文字）
   ↓
① 视觉识别 Agent   模型   OCR 提取原文、机构名、联系方式
   ↓
② 规则比对 Agent   规则   14 类特征 / 314 关键词，精确通道（高精度）
   ↓                      含否定语境、科普语境、合法术语白名单三重误判防护
③ 语义识别 Agent   模型   覆盖规则库穷举不到的口语与变体（高召回）
   ↓                      每条结论必须引用原文，引文对不上即丢弃
④ 主体核查 Agent   规则   资质编号、主体性质、成交渠道疑点 + 官方核查入口
   ↓
⑤ 法规引证 Agent   规则   为每条命中调取对应法规条文（13 条）
   ↓
⑥ 汇总裁决 Agent   模型   把客观判定转述成小白能懂的话
   ↓
输出审查层         规则   拦截投资建议 / 涨跌预测 / 安全保证 / 法律与合规定性
                          + 检测模型编造的数字
```

### 为什么需要两条通道

规则库是照着**正规广告文案**建的（「保本保息」「预期年化收益」「代客理财」），
但真实骗局在微信里说的是**大白话**：

| 输入 | 规则通道 | 语义通道 |
|---|---|---|
| 「老弟，你听我的，钱打过来我给你操作，一个月不翻倍我给你补」 | 0 条 | **3 条** |
| 「咱们村的项目，投一万，每个月给你三百，拉个亲戚来还有奖励」 | 0 条 | **2 条** |
| 「跟存款差不多，但收益高得多」 | 0 条 | **2 条** |

关键词库永远穷举不完，所以必须有第二条通道。但语义通道**不等于让模型自由裁量**，有三条硬约束：

1. 只能从既有特征分类表中选择，不得自创类别 —— 因此法规引证依然成立
2. 必须给出原文中**真实存在**的引文，引文对不上直接丢弃 —— 可验证性
3. 引文要过与规则通道**完全相同**的否定/科普语境检查 —— 标准一致

模型在这里承担的是「召回」，判定标准仍然由我们定义。报告里每条命中都标注来源
（规则命中 / 语义识别），被丢弃的项也展示出来。

**核心设计原则：判定归规则，转述归模型。**
风险等级、命中项、法规依据全部由确定性规则产生，模型只负责"提取"和"讲人话"。
所以换模型不改变判定结果，且每条结论都能追溯到法规原文。

三道防线保证模型不会说出不该说的话：

1. **提示词约束** —— 明确禁止引入原文之外的数字、统计、机构名与案例
2. **输出审查层**（`lib/rules/guard.ts`）—— 确定性拦截投资建议、涨跌预测、安全保证、
   诈骗定性、合规定性；并检测模型编造的数字，一旦出现即整段丢弃、回退模板
3. **兜底与超时** —— 模型转述 8 秒硬超时；`green`（暂未发现明显问题）这一档
   **一律使用模板措辞**，因为它最容易被误读为"这个产品安全"，措辞必须逐字可控

实测端到端 3–7 秒（真实 OCR + 模型转述）。

## 目录

```
data/                     知识库（可版本控制、可溯源）
  violation-patterns.json   违规话术特征库 + 否定/科普语境规则 + 术语白名单
  regulations.json          法规条文库（officialText 待团队逐条核对）
  glossary.json             术语表（24 条）
  samples.json              自制仿真演示样本（虚构，不指向真实企业）
  market-snapshot.json      市场基准数据快照（待填真实值）
lib/
  rules/                    规则引擎：匹配、脱敏、主体核查、输出审查、术语
  llm/                      模型适配层（mock / qwen，可扩展 GLM / Kimi / Claude）
  report/                   确定性总结生成器 + 模型提示词
  finance.ts                IRR / 应急金计算
app/api/shield/             五智能体 SSE 流水线
tests/                      回归测试
```

## ⚠️ 交付前必办

1. **逐条核对法规原文**：`data/regulations.json` 中 `officialText` 全为 `null`、`verified: false`。
   前端会明确标注「条文原文待核对」。答辩前必须补齐，条号错误是致命伤。
2. **填写市场基准数据**：`data/market-snapshot.json` 三项数值均为 `null`，需从公开来源抄录并标注日期。
3. **演示样本**：公开演示只使用 `data/samples.json` 中的自制仿真样本，
   **不得使用可识别到真实公司的截图**。
